# QQ Linux 部署与验证

QQ 使用独立容器、独立配置目录和独立 HTTPS 入口。手机端共用现有的动画、侧滑、WebSocket 增量画面、清晰度、输入恢复和可选 Web Push；桌面适配器根据 QQ 会话列和编辑区的分隔线识别布局，未识别的登录页或布局保留全览操作，并关闭手机发送控件。

## 安装

在源码目录创建新部署，路径不能是已有微信部署：

```sh
bash scripts/setup.sh --client qq /absolute/path/qq-remote
cd /absolute/path/qq-remote
bash doctor.sh
docker compose up -d --build
docker compose ps
```

以 root 运行时，明确设置普通用户的 PUID / PGID。脚本为 QQ 设置 `CHAT_CLIENT=qq`、`CLIENT_DOCKERFILE=Dockerfile.qq`、独立镜像和容器名，以及本地后端端口 `5805`。仍使用统一的 `docker-compose.yml`；不要通过修改现有微信目录的 `CHAT_CLIENT` 来混用账号数据。

为 `127.0.0.1:5805` 配置 HTTPS 代理并保留 Host、Origin 和 WebSocket Upgrade。先打开 `/index.html`，通过手机 QQ 完成桌面客户端登录，再打开 `/mobile/` 并使用 `.env` 中的网页登录密码。QQ 与微信使用不同 Cookie 名，同一个 NAS IP 的不同 HTTPS 端口可以同时登录。

`Dockerfile.qq` 从多架构 LinuxServer Selkies 基础镜像构建，在当前架构下载腾讯官方 Linux QQ 安装包，校验 SHA-256 和包架构，再安装画面处理和推送依赖。当前固定 QQ 3.2.32，同时支持 `amd64` 与 `arm64`；不分发重新打包的客户端镜像。容器启动时无需再下载依赖。

## iPhone 竖屏与高清显示

QQ 安装脚本默认写入 `QQ_UI_SCALE=3`、`DESKTOP_WIDTH=4200`、`DESKTOP_HEIGHT=6000`。QQ 以 3 倍原生像素绘制文字，手机根据实际屏幕像素比绘制画布，最高支持 3 倍；会话列和聊天区分别裁切成竖屏，标题栏保留可读字号与右侧操作按钮。较长的桌面为本地滑动提供历史画面余量，聊天窗口稍微加宽以降低显示倍率。键盘弹出只改变手机端可见区域，底层桌面的尺寸不代表手机需要横屏。

群聊会识别右侧公告与成员列，手机只显示消息区域。输入与发送坐标按消息区域右边界计算；群聊窗口在桌面余量内补偿侧栏宽度，让群聊和私聊保持接近的比例。

聊天文字与会话列表使用独立比例：原生聊天窗口较窄，消息自动换行且文字稍大；会话列表密度为原比例的 78%，搜索栏保持原大小。两者都保留 3 倍原生绘制与手机实际像素密度。切换时校验编辑区和截屏范围，画面与布局一致后再完成过渡。

点选会话列表顶部的搜索栏，会出现手机本地搜索输入框并唤起软键盘；提交后点选 QQ 原生搜索结果。清空搜索内容后提交可恢复普通列表。搜索和发送分别校验当前窗口与会话，搜索请求不会进入消息输入区。

已有 QQ 部署可在 `.env` 添加或更新上述三项，然后运行 `docker compose up -d --force-recreate`；仅复制前端代码不会改变桌面尺寸。QQ 的“设置 → 通用”中可调大消息字号，让宽聊天区缩放到手机后仍易于阅读。内网默认使用无损画面，外网默认使用原分辨率高清画面；菜单可切换省流模式。高 DPI 会增加内存、编码和网络开销，资源有限时可改成 `QQ_UI_SCALE=2`、`DESKTOP_WIDTH=2800`、`DESKTOP_HEIGHT=4000` 后重建容器。

Retina 画面按最多 256 行的小块逐个解码，完整一帧就绪后再显示。滚动优先在同一画布移动像素，临时画布和结束的过渡快照主动释放；解码超时自动重新获取完整画面。iOS 触摸中断、键盘改变视口和滚动请求使用过期布局时可恢复，旧会话的迟到响应不会覆盖新会话。

QQ 每个完整画面按手机实际像素密度生成滚动缓存，随后本地滑动通过独立合成图层移动已缩放的像素，避免逐帧重绘整个视口。下一帧逐块解码时仍可滑动上一幅完整画面；新画面与滚动坐标一起更新，导航快照包含当前可见的合成图层。缓存上限为 8 百万像素，较长的列表只缓存可视区域周围的一段；若单个视口仍超出上限则直接绘制。进入后台、重连或全览时释放缓存；预取等待下一幅画面，避免手势在同一帧堆积重复滚动请求。

## 内网 HTTPS

在源码目录运行，QQ 与微信代理使用不同容器名和端口：

```sh
CHAT_ROOT=/absolute/path/qq-remote \
LAN_IP=192.168.1.20 LAN_CIDR=192.168.1.0/24 LAN_PORT=5844 \
bash scripts/setup-lan.sh
```

代理从部署 `.env` 读取 QQ 的 HTTP_PORT，不会固定转发到微信端口。通过已信任的 HTTPS 外网入口打开 `/mobile/lan-setup.html`，安装本机根证书并在 iPhone 开启完全信任。若两个应用共用已受信任的本机 CA，可以由部署者复用该 CA 和对应 IP 服务器证书；私钥始终留在 NAS 私有目录。

## 推送

按 README 的 Web Push 配置方法，在 QQ 部署自己的 `config/mobile/push/settings.json` 设置其公网 HTTPS origin。为 QQ 单独生成的 VAPID 密钥和手机订阅不会复用微信订阅。QQ 客户端需要允许系统新消息通知；后端只监听来自 QQ 的标准桌面通知。

iPhone 需要先将 QQ 外网入口添加到主屏幕，再从主屏幕打开，在菜单开启“消息推送”，允许系统通知，并发送测试通知。测试通知被推送服务接受和手机实际显示是两个验证步骤。真实新消息是否产生通知，还取决于 QQ 的通知设置、静音会话及客户端当前状态。

## 版本与升级

固定客户端版本和官方包校验值，避免上游更新在未经验证时改变窗口和输入行为。QQ 官方更新可能改变布局、菜单、发送确认和通知，应先在独立测试目录构建，再验证后替换镜像。建议在 QQ 的“设置 → 通用”关闭自动更新，通过重新构建镜像升级；界面内更新可能在重建容器后丢失。

升级项目代码时保留 `.env`、账号配置、`session.key`、`push/`、证书和私人网页资产。不要用整目录覆盖的方式更新带有私人图标的 `config/mobile/web/`。公开源码只包含原有中性图标，项目名称保持 `nas-chat-mobile`。

## 验证范围

原生 x86_64 与 ARM64 容器均完成启动、X11 颜色与窗口、输入、剪贴板、推送加密依赖、nginx 登录/API 和无损 WebSocket 首帧验证。QQ 登录页不会启用微信发送坐标；QQ 桌面布局的列表/聊天裁剪、点击映射和安全拒绝有离线回归检查。

涉及真实账号时，按以下顺序检查：选中会话、返回与侧滑回弹、连续发送和输入恢复、图片粘贴/文件发送、菜单与图片查看器、断网恢复、锁屏测试通知，以及其他账号发来的真实新消息。发送测试应使用自己的设备会话；冒烟脚本仅用于未登录的临时容器。
